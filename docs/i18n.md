# Çoxdillilik (az / en / ru)

Tətbiq üç dildədir: **Azərbaycan dili (standart)**, ingilis və rus. Bu sənəd dilin necə seçildiyini, mətnlərin harada saxlandığını və yeni mətnin və ya yeni dilin necə əlavə olunduğunu izah edir.

## Dil necə seçilir

| Kim | Qayda |
|---|---|
| **Qonaq** (daxil olmamış müştəri) | Bu cihazda seçdiyi dil. Seçməyibsə, şirkətin standart dili (Parametrlər → Standart dil), o da yoxdursa `az`. |
| **Müştəri** | Profildəki dil (Parametrlər → Dil). SMS-lər də bu dildə göndərilir. Bütün cihazlarda eynidir. |
| **İşçi, platforma admini** | Profildəki dil (Hesabım → İnterfeys dili). Emaillər də bu dildə gəlir. |
| **API xətaları** | Sorğunun dili: istifadəçinin dili, `Accept-Language` başlığı və ya şirkətin standart dili. |

## Mətnlər harada saxlanılır

| Nə | Harada |
|---|---|
| Frontend interfeysi | `fe-tapstamp/src/locales/{az,en,ru}/{common,auth,profile,admin,errors}.json` |
| Backend (xəta mesajları, SMS, email, CSV başlıqları) | `be-tapstamp/src/main/resources/i18n/messages_{az,en,ru}.properties` |
| Şirkətin məzmunu (ad, filiallar, hədiyyə, hüquqi sənədlər) | Bazada JSONB: `{"az": "...", "en": "...", "ru": "..."}`. `az` məcburidir; tərcümə yoxdursa, az versiyası göstərilir. |

Kodda istifadəçiyə görünən mətn yazmaq **qadağandır**: ESLint (`i18next/no-literal-string`) bunu xəta kimi göstərir.

## Yeni mətnin əlavə edilməsi

Addımlar README-də, "Yeni tərcümə açarının əlavə edilməsi" bölməsindədir. Qısaca:
1. Açar **3 dilin hamısına** birdən əlavə olunur.
2. Sayla dəyişən mətnlər üçün cəm formaları yazılır:
   - az və en: `_one`, `_other`;
   - ru: `_one`, `_few`, `_many`, `_other`.
3. Yoxlama:
   - `npm run typecheck` — mövcud olmayan açar xətadır;
   - `npm test` — 3 dilin açarları və cəm formaları eyni olmalıdır;
   - backend-də `MessagesParityTest`.

Hüquqi sənədlərdə `{{stampRules}}` və `{{rewardRule}}` yer tutucuları var. Tətbiq onları şirkətin cari möhür və hədiyyə qaydası ilə, oxucunun dilində əvəz edir (`profile.json` → `legal.rules`).

## Yeni dilin əlavə edilməsi (məs. türk dili)

1. **Frontend:**
   - `src/shared/i18n/languages.ts` faylında `SUPPORTED_LANGUAGES` və `LANGUAGE_CODES`-a dili əlavə edin;
   - `src/locales/tr/` qovluğunu yaradıb bütün namespace fayllarını tərcümə edin;
   - i18n konfiqurasiyasında (`src/customer/i18n.ts`, `src/admin/i18n.ts`) resursları qoşun.
2. **Backend:**
   - `Language` enum-una dəyəri əlavə edin;
   - `messages_tr.properties` faylını yaradın;
   - bazadakı `CHECK (preferred_language IN (...))` məhdudiyyətlərini yeni miqrasiya ilə genişləndirin.
3. **Şirkətin məzmunu:** `LocalizedText`-ə yeni sahə əlavə olunmalıdır. Admin formalarında da yeni dil sahəsi göstərilməlidir.
4. Paritet testləri (`npm test`, `MessagesParityTest`) bütün açarların tərcümə olunduğunu yoxlayacaq.

## Formatlar

- **Tarixlər:** Azərbaycan dilində əl ilə qurulur ("7 oktyabr 2026"), çünki bəzi brauzerlərin ICU məlumatı natamamdır. Digər dillərdə `Intl` istifadə olunur.
- **Nisbi vaxt:** az dilində əl ilə ("44 dəqiqə əvvəl", "dünən"), digər dillərdə `Intl.RelativeTimeFormat`.
- **Saat qurşağı:** bütün vaxtlar bazada UTC-dədir. Göstərişdə və "gün" hesablamalarında (gündəlik limit, analitika) şirkətin saat qurşağı istifadə olunur.
